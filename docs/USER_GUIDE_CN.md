# Future-Code 用户使用说明

Future-Code 用于持续推进软件研发、科研分析和其他需要反复执行、检查与改进的项目。你提供目标、材料和验收要求；系统据此安排工作、调用已配置的模型与工具，并整理过程和结果。

## 1. 开始一个项目

1. **选择项目目录。** 新项目使用空目录；已有项目请确认目录和代码版本正确。重要工作开始前，建议先提交或备份现有修改。
2. **写清楚要完成什么。** 说明目标、现状、限制条件、交付物和“怎样算完成”。例如：“分析这个数据集，给出可复现的基线结果；保留运行脚本，并列出尚未验证的假设。”
3. **提供所需材料。** 可将项目文件、数据说明、参考资料、验收规则和团队经验放入项目，或按当前版本支持的方式提供。只提供完成任务所需的访问权限。
4. **配置模型服务。** 按安装版本的设置说明填写兼容的模型服务地址和模型名称。密钥应放在受保护的环境变量或密钥设置中，不要写进提示词、项目文档或代码仓库。模型调用可能产生服务费用，并受服务商额度限制。

## 2. 规划与执行

先让 Future-Code 根据目标提出任务计划，再检查任务范围、依赖关系、预期改动和验收方式。发现遗漏时直接补充要求；确认计划符合预期后再启动执行。需要命令行入口的版本可使用 `/swarm-plan` 生成计划，再使用 `/swarm run` 执行已审阅的计划；具体命令以安装版本的帮助信息为准。

执行期间可查看任务状态、阶段性结果和失败原因。任务中断时，使用当前版本提供的恢复或继续操作接着处理，并查看哪些步骤已完成。涉及删除、覆盖、对外发布、真实账户操作或其他有影响的操作时，先检查具体目标和变更内容，再明确授权。

## 3. 常用功能

- **任务拆解与并行处理：** 将较大的目标分成可检查的小任务；相互独立的工作可并行推进。
- **代码与资料处理：** 根据项目配置调用模型和获准工具，生成或修改文件、分析数据、运行约定的检查。
- **项目知识与经验：** 提供团队的术语、流程、技能和历史经验，帮助后续任务了解项目背景。重要经验应注明适用范围和来源；需要事实支撑的结论仍应检查证据。
- **过程记录与恢复：** 查看任务进展、运行记录和已保存的结果；中断后可按版本支持的方式恢复。
- **验证与对比：** 查看配置的检查是否通过，并在条件允许时比较基线与改进方案。只有实际执行并留有记录的数据才是实测结果；缺失数据应保持未确认。

## 4. 检查结果并交付

完成后，检查最终文件、代码差异、测试或分析记录、失败项和未解决问题。确认交付物符合最初约定；如不符合，指出具体差距并要求继续处理。对重要结论，查看其依据和验证状态，不要只依据模型生成的文字判断是否成功。

需要将代码并入主分支、提交研究结论或分享材料时，先审阅变更和敏感信息，再使用项目既有的审核与发布流程。Future-Code 可协助准备材料，外部发布仍应由有权限的人检查确认。

## 5. 使用建议

目标越清楚，执行越稳定。把大任务分阶段提出，为每阶段写出可观察的完成条件；首次运行先用小范围任务熟悉流程。定期检查权限、费用、数据来源和生成结果。不要输入不应交给所选模型服务或工具处理的机密、个人信息或受限制数据。

具体按钮、参数和可用功能会随安装版本及项目配置变化，请以该版本自带的帮助信息为准。
