# 已授权任务的自主执行与重复确认修复

## 问题与处理结果

用户已经要求推送本次修改，并持续拉取、重建和同步时，系统应先完成当前推送，再继续原有同步流程。不能将这两项已授权工作重新列为选项，让用户再次回复“go”或选择其中一项。

本次以 `bd410dbbf0f4db1286956580822ce3501db9ba64` 为基线，处理以下执行路径，并纳入后续反馈中的 `/loop` 与会话状态串扰问题：

| 原因 | 修复后的行为 |
| --- | --- |
| 系统提示要求再次确认推送，与自主执行要求冲突 | 同一授权范围内的后续步骤继续执行；多项兼容任务按依赖顺序完成 |
| 自动目标识别漏掉 push、commit、sync、run、continue 等指令，短指令也被忽略 | 明确的执行指令，包括“Run tests”，自动建立持续执行目标 |
| 问题工具会在目标尚未完成时直接打开用户选择界面 | 在进入权限处理和界面前检查宿主目标，向模型返回继续执行指令，不代填用户答案 |
| 模型主动进入计划模式，额外请求方案批准 | 自主目标内直接分析和规划；只有用户要求互动时保留相应界面 |
| 模型写了 completed，但推送、同步等里程碑仍未完成 | 保留当前目标，指出第一个未完成里程碑，继续依次执行 |
| “Say go”被写为 permissions 类型的外部阻塞 | 将重复确认视为可自行处理的问题；实际拒绝访问或缺失能力仍保留具体诊断 |
| 可选的 token 续跑先于目标检查 | 先处理当前目标、完成状态和执行上限；暂停和复核状态不能被 token 续跑重新激活 |
| `/loop` 只有提示文本，没有登记宿主目标，因而被旧的 `test arg / REVIEW` 覆盖 | 在可信的人类命令入口登记完整循环任务，按真实命令来源区分连续执行与定时调度 |
| 同一目录中的多个会话共用目标、报告、预算和暂停状态 | 按会话隔离这些文件，旧请求的延迟结果只能更新其原属会话 |
| 循环默认执行五轮后再次询问，或一轮完成后进入复核 | 连续循环跨越已完成轮次；带停止条件的循环保留原条件，真正满足条件后才进入复核 |
| 定时命令展开为可见的 user 形消息，可能被误认为新的人类授权 | 依据展开前的来源及钩子处理结果登记目标；定时消息、模型调用和工作线程不能冒充人类指令 |

## 对用户示例的处理

当模型再次输出“Push bd410db，然后继续 periodic sync cycles；say go for both or pick either”时，执行器会保留原目标及授权，给模型返回纠正指令，要求核对真实状态并按依赖顺序完成两项工作。模型声明一个子任务完成，不能结束仍有未完成步骤的总体目标。

“go”“go for both”“do both”等简短回复用于恢复既有暂停目标，不能被当成一个新的总体目标，也不能凭空授权不明确的工作。

## 监测循环与会话隔离

对于用户提供的 `/loop continue: monitor ...`，宿主保留完整的监测、修复、验证、构建、提交、推送和恢复要求。旧目标如果是 `test arg / REVIEW`，明确输入的新循环会自动建立自己的执行合同，无需用户再选择“继续监测”还是“处理 test arg”。

每个会话使用 `.future-code/goals/<session-id>/` 下独立的 `goal-autonomy.json`、`goal.md` 和历史记录。实时目标锚点、压缩后的目标锚点、`/goal` 和 `/save` 均指向所属会话的报告。切换会话后，旧请求的延迟失败处理仍绑定原会话，不能暂停刚切换过去的任务。

旧版目录级文件没有会话归属证据，保留原文件但不会自动导入新会话。健康报告将这类内容标为“legacy goal (session unknown)”，避免把历史测试目标算作最新会话的目标。新收到的明确循环指令会自动登记，不要求用户处理旧文件。

内置连续循环与定时循环分别处理：前者没有默认五轮上限，完成一轮后仍继续；后者保留本地定时器、到期时间与任务 ID，每次执行完成后把控制权交回调度器，避免前台空转或重复创建任务。后续定时触发不会继承前台目标的复核锚点，也不能改写前台目标、报告或预算；用户消息与定时消息分别调度。两者都遵守实际停止指令和资源边界。

## 权限、暂停和必要的人机交互

本次没有修改工具的实际访问权限。普通推送授权不包含强制推送，代码开发授权不包含任意生产发布或支出。用户明确暂停、调用者轮数上限、累计续跑上限及独立验收继续有效。

普通补充信息和约束不会取消用户的暂停。用户为真实外部阻塞补充了缺失信息后，系统可以在剩余预算内继续，保留原目标和累计消耗，无需再索要一次“continue”。

默认由系统自行处理实施选择。如果用户主动要求“Ask me to choose between the designs”，主线程会记录这项交互要求，允许相应问题；用户随后要求“不再问我”时关闭该交互。它只允许对话交互，不增加任何外部执行权限。子智能体仍向协调者返回阻塞和所需输入，不能自行打开面向用户的对话框。

模型连续返回决策菜单，或连续调用被拒绝的问题、计划批准工具时，系统会执行有界纠正。两次自动纠正后仍没有实际工具动作，则报告模型执行契约异常并保留目标和证据，不再要求用户反复回复“go”。这项诊断不会冒充网络中断，也不会伪造成功。
