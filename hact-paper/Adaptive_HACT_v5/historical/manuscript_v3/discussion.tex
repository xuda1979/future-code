\section{Practical Deployment and Limitations}\label{sec:limits}
\paragraph{When the mechanism is useful.}
Learned display layouts are most useful when a stable check registry is poorly aligned with repeated completion groups, certificate streams are stored or transmitted frequently, and compilation can be amortized over many candidate verifications. The fresh source runs demonstrate substantial format-specific byte savings without changing checker execution. Stable-ID tickets are useful even without savings: an agent cannot certify a new candidate with an old layout's optimistic status. A trusted gate that rejects altered tests addresses a concrete failure mode that narrative reporting does not solve.

\paragraph{When it is not useful.}
An already aligned small registry, globally active checks, or cheap local tests can leave little or no benefit. The harness fixture supplies a direct example. When scripts finish in milliseconds, snapshotting and protected-contract checks can dominate; deploying the strict wrapper merely to save bytes may be a poor choice. Under fast drift, adaptation can spend more on installations than it recovers. A stable layout or a conservative window rule is then a meaningful operational alternative. This paper reports all these cases rather than treating them as implementation mistakes to tune away after seeing the results.

\paragraph{Learning limitations.}
Jaccard similarity is a proposal heuristic, not a causal model. Pairwise evidence cannot recover arbitrary higher-order dependence. Spectral and clustering proposals explore only three orders, and the exact compiler does not make that finite search globally optimal. The source data are controlled mutations, many sharing files; replaying 33 previously published cases is not a new independent test set. The strict wrapper avoids unsafe test selection by requiring complete passes, but that conservatism limits opportunities to save checker execution time.

\paragraph{Online limitations.}
The catalogue is frozen using explicit calibration regimes. The controller is not an open-ended topology generator and its proof does not cover changing catalogues without restarting a newly analyzed learning epoch. The sequence must be exogenous to the selected display layout. If a manager changes its reasoning or task schedule in response to different summaries, the cost vector may become reactive and our tracking argument is not sufficient. The bound is intentionally explicit and can be loose; empirical tuned-window performance is sometimes better. Floating-point implementations approximate exact-arithmetic probability updates, and the statistical experiments are not formal verification of every numerical corner case.

\paragraph{Verification and systems limitations.}
The guard is single-process and uses local atomic checks; Future Code uses a single-host supervisor and SQLite. Neither component establishes multi-host consensus, Byzantine resilience, remote attestation, or atomic external deployment. File copying and hashes cannot sandbox untrusted Python tests. The operator must use an outer isolation boundary, protect contracts/checkers from candidate writes, and review that all relevant inputs are included. Environment fingerprints cannot freeze an unrecorded remote service or eliminate test flakiness. Missing or unstable evidence must remain unknown or force an explicit new epoch.

\paragraph{What remains unmeasured.}
No hosted LLM generated, selected, or repaired patches in these runs. No actual model token usage, API bill, natural historical defect campaign, SWE-bench score, multi-host operation, Windows execution, GPU/NPU training, or long-duration production service was measured. The harness plug-in is usable now, but a hosted-agent study still requires an approved model endpoint, budget, frozen issue cohort, paired seeds, and executable acceptance protocol. The artifact supplies a configuration path without fabricating those outcomes.

\section{Conclusion}
Adaptive HACT makes verification layout a learned, priced, and revocable representation of an unchanged acceptance contract. Stable semantic IDs allow evidence to survive a display-only reorder without allowing stale tickets to survive it. Full completion hyperedges, rather than pairwise affinities alone, determine exact certificate cost; online migration must be charged explicitly. The measurements establish genuine byte savings on misaligned source-verification workloads, clear failure modes under drift, and a real harness integration whose additional protection has a measurable runtime cost. The result is not a claim that more agents reason better, but a concrete method for controlling the cost and validity of the evidence they rely on.
