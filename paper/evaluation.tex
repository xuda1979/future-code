\section{Implementation and Experimental Protocol}\label{sec:experiments}
\subsection{Prototype and relationship to the agent runtime}
The supplied Future Code Control v1.2.0 archive is a Python companion with hierarchical tasks, bounded contexts, durable state, and executable gates. We extracted it, checked its ZIP integrity, and independently reran its existing suite: 263 tests passed. This establishes the available baseline artifact, not an empirical advantage of HACT.

HACT is implemented as a separate research package. Its tree optimizer, certificate kernel, experiments, and tests do not replace the baseline scheduler or claim production integration. A future adapter would consume trusted gate events and dependency closures, then supply bounded certificate packets to existing task coordinators. Model-generated explanations remain separate from canonical verdicts.

The evaluated environment was Linux x86\_64, Python 3.13.5, NumPy 2.3.5, SciPy 1.17.0, and Matplotlib 3.10.8. All experiments ran locally on CPU. No hosted language model, paid inference, external deployment, or GPU/NPU was used. Planner timings are wall-clock observations in this container, not dedicated-hardware throughput measurements. The exact environment record is included.

\subsection{Common baselines and budget}
All methods share the same registry order, invalidation sets, checker outputs, and $(H,S,C)=(512,320,3072)$ byte format. Fixed-$b$ baselines build bottom-up consecutive groups of at most $b$ children; singleton groups are promoted without inserting unary nodes. We report fixed arities 2, 4, and 8. A stronger \emph{tuned fixed} baseline chooses one arity from 2 through 8 by minimizing \emph{training} cost, never test cost. The \emph{marginal} baseline uses Equation~\eqref{eq:independence} with the exact same dynamic program as HACT. No baseline is allowed to drop checks, change leaf order, or weaken the context cap.

A flat, all-obligation scanner would require $512+320n$ bytes in one packet: 41,472 bytes at $n=128$. It violates the cap and is therefore not used as a competitive constrained baseline. It remains useful as a conceptual correctness oracle, not as an artificially weak system against which to advertise scaling.

\subsection{Synthetic invalidation study}
The primary protocol was recorded before the main measurements. There are six families, 20 independent seeds per family, and $n=128$ gates. Each seed has 512 training episodes and 2,048 held-out episodes from independent random streams. In total there are 61,440 training and 245,760 held-out episodes. The retained Boolean masks permit reconstruction of every set.

For each seed and method, the outcome is the mean held-out bytes per episode. Percentage reduction is computed \emph{within each seed} as $100(1-\overline L_{\mathrm{HACT}}/\overline L_{\mathrm{baseline}})$ and then averaged across seeds. Confidence intervals are two-sided 95\% Student-$t$ intervals over independent seeds. We do not count 2,048 correlated method comparisons within one workload as 2,048 independent replications. Intervals are unadjusted descriptive intervals, not family-wise corrected hypothesis tests.

\subsection{Scaling and exploratory sensitivity}
The prespecified scaling study uses clustered workloads at $n\in\{32,64,128,256,512\}$ with four seeds per size. The $n=128$ values reuse matching seeds from the primary study and are not additional independent trials. The remaining sizes contribute 32,768 held-out episodes. We retain tree depth, maximum packet bytes, refreshed-node counts, full-refresh bytes, and optimizer wall time.

After the main runs, exploratory checks vary training count (32, 128, 512), impose depth 3 or 4, randomly permute the shared leaf order, and evaluate a cluster-trained tree on independent invalidations. These four-seed diagnostics are explicitly post-main-study analyses; they did not select the primary configuration or determine which primary results to report.

\subsection{Executable mutation microbenchmark}
A separate fixture contains 16 generated Python modules. Module $i$ implements $f_i(x)=x+i$. Four unit obligations evaluate $x\in\{-2,0,5,19\}$. One cross-module obligation checks $f_i(f_{(i+1)\bmod16}(3))=3+i+((i+1)\bmod16)$. There are therefore 80 obligations in a fixed order.

For each of six seeds, 16 pairs of edits select one to three adjacent modules with a hotspot-weighted starting position. The first edit deliberately adds one to the first selected module's output; the second restores the intended function. Revision comments ensure that all selected source hashes change. Each seed's tree is learned from 512 independent training module-edit sets, translated to complete declared invalidation closures. No check result from the 32 evaluation snapshots selects a tree.

Each snapshot is immutable source text. A fresh Python subprocess executes the affected predicates; a separately launched full-registry invocation supplies the oracle comparison. Both use the protected checker, so this is independent \emph{execution scope}, not an independently designed semantic oracle. All five certificate layouts consume the same actual check records. We measure the lengths of packets produced by the kernel and require equality with Equation~\eqref{eq:episode}. We also attempt to use the previous publication ticket after each edit and require its rejection. The mutations are scripted; no agent is credited with discovering or repairing them.

\subsection{Executable checks and actual serialization}
Across the six executable seeds there were 192 evaluated snapshots: 96 faulty and 96 repaired. The selective path ran 1,992 gate checks, while the offline full-registry oracle ran 15,360. Initial certification adds 80 checks per seed and is reported separately from snapshot costs. Selective-check counts are the same for every tree; HACT does not claim their reduction as a topology benefit.

All five layouts agreed with the full oracle on every snapshot. There were zero falsely passing roots among the 480 faulty snapshot--layout decisions, and all 480 repaired decisions passed. All 960 prior-ticket attempts after an edit were rejected. Actual packet lengths agreed exactly with the analytical episode cost, and no packet exceeded the cap. These are finite tests of the declared fixture, not a general estimated failure probability for production.

\subsection{Exploratory diagnostics and failure modes}
For the four diagnostic clustered seeds, using only 32 training episodes produces 8,855 bytes per episode and depths 15--27; 128 episodes gives 6,929 bytes, and 512 gives 6,840 bytes. Sparse empirical data can leave many intervals apparently inactive, leading the unconstrained tie-breaking rule to choose long branches. There is no theorem that a small context automatically induces a good decomposition or adequate training coverage.

A hard depth-three variant averages 6,991 bytes, approximately 2.2\% above the 512-example unconstrained result, while reducing all depths to three. Depth four averages 6,836 bytes and happens to be slightly better on held-out data despite a restricted feasible family; empirical optimum need not minimize test risk. These exploratory observations support exposing depth as a separate policy parameter rather than prescribing eight children everywhere.

Randomly permuting the common leaf order raises HACT's mean traffic from 6,840 to 16,917 bytes; the permuted tuned-fixed baseline averages 21,418. Thus order materially affects absolute cost, even when correlation-aware placement retains a relative advantage on these four seeds. HACT's optimality theorem cannot be used to claim order-invariant efficiency.

Finally, applying the cluster-trained unconstrained tree to independent test episodes gives 18,007 bytes versus 16,402 for the cluster-selected fixed baseline, a degradation of about 9.8\% by the ratio of these diagnostic means. The stationary selection theorem does not protect against this shift. An operational system needs drift monitoring and a conservative fallback; a learned tree should not be frozen indefinitely merely because it was once optimal on training traces.

\subsection{Implementation verification}
The HACT test suite contains 90 passing cases. It compares the unconstrained optimizer with exhaustive ordered-tree enumeration through seven leaves and the height-constrained optimizer through six leaves. Other cases validate expected-cost identities, the four-leaf separation, disjoint coverage, unknown propagation, stale evidence, tampered displays, publication races, byte limits, and topology-switching freshness. Ten randomized tests exercise 60 edit/revalidation/tree-switch cycles each. A subprocess test independently executes the 80-gate fixture and detects six failed predicates after a single-module fault.

These tests use the actual runtime modules of the research package. The saved failing stale-cache regression demonstrates detection of a genuine implementation error before correction. Passing tests and informal mathematical proofs are not a machine-checked verification of the full implementation. The original companion's 263 passing tests and HACT's 90 passing tests are distinct suites, not a combined claim that the new algorithm was already integrated into the original runtime.

An additional retained-data auditor does not import the optimizer, kernel, producer cost helpers, or fixture checker. It recomputes interval traffic directly from Boolean masks, validates tree coverage and source hashes, independently evaluates the fixture arithmetic, and reproduces seed-level summaries. All primary, scale, and executable records pass this audit; a deliberately corrupted tree is rejected. This is a separate code path, not independent human verification, and exploratory sensitivity records are outside its audit scope.

\subsection{Hybrid optimizer and scaling characteristics}\label{sec:hybrid}
The TypeScript port introduces a hybrid optimizer that uses the exact DP for
subtrees with at most $n_{\text{thresh}}$ gates and a multi-strategy greedy
heuristic for larger subtrees. The greedy top level evaluates even splits,
$p$-weighted boundary splits, and local-search refined splits, then selects
the split that minimizes exact subtree costs. With $n_{\text{thresh}}=128$,
the hybrid matches the exact DP for all $n \le 128$ while scaling to $n=512$.
